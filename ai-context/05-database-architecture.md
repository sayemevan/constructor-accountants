# 05 — Database Architecture

Load when: changing the Prisma schema, writing migrations, writing queries, or designing a new entity.
Tenancy mechanics are in `06-multi-tenancy.md`; financial tables are explained in `24-financial-model.md`.

**Rule:** before adding an entity or column, search `apps/api/prisma/schema/` and this file. Do not invent
parallel tables for concepts that already exist (e.g., no `clients`, `suppliers`, `expenses`, `payments`
tables — see Party and Finance).

## 1. Conventions

| Topic | Convention |
|---|---|
| Naming | Tables `snake_case` plural (`financial_transactions`); columns `snake_case`; Prisma models `PascalCase` singular with `@@map`/`@map` |
| Primary key | `id uuid` — **UUIDv7** generated by the app/Prisma (`@default(uuid(7))`), time-ordered for index locality |
| Tenant key | `tenant_id uuid NOT NULL` on every tenant-owned table; FK → `tenants.id` |
| Tenant-safe FKs | Every tenant-owned table has `UNIQUE (tenant_id, id)`; references to tenant-owned rows use **composite FKs** `(tenant_id, x_id) → x(tenant_id, id)` so a row can never point to another tenant's row |
| Human numbers | `code`/`*_no` (e.g., `PRJ-2026-0007`) from `number_sequences`, `UNIQUE (tenant_id, code)`; never used as FK |
| Money | `numeric(18,2)`; quantities/rates `numeric(18,4)`; hours `numeric(6,2)`; percentages `numeric(5,2)` |
| Currency | `char(3)` ISO 4217; MVP: always the tenant base currency (validated) |
| Dates | Business dates `date`; instants `timestamptz` (UTC) |
| Enums | Postgres enums via Prisma for closed sets; lookup tables for tenant-configurable sets (e.g., finance categories) |
| Text search | `citext` for emails; `pg_trgm` GIN indexes on names used in search |
| JSON | `jsonb` only for genuinely schemaless data (settings blob validated by Zod, audit diffs, custom contract terms, snapshots) — never for queryable business fields |
| Booleans | `is_*`/`has_*`, NOT NULL with default |

### Standard columns
- **Mutable business records:** `created_at`, `updated_at`, `created_by_id`, `updated_by_id`, `version int`
  (optimistic locking; increment on every update).
- **Immutable records** (transactions, allocations, audit logs, status history, attendance lock history):
  `created_at`, `created_by_id` only; no `updated_*`; app DB role has no UPDATE/DELETE where noted.
- **Archivable master data:** `archived_at timestamptz NULL`, `archived_by_id`. Default queries exclude archived rows.

## 2. Deletion policy (soft delete matrix)

| Category | Tables | Policy |
|---|---|---|
| Financial | financial_transactions, payment_allocations, finance_obligations(+lines), payroll_runs/items/lines, subcontract_bills, client_bills, rental_charges | **Never deleted.** Draft/pending → `CANCELLED`; posted → void via reversal. |
| Master data | parties, employees, projects, machines, money_accounts, finance_categories, roles | **Archive** (`archived_at`) once referenced; hard delete only if never referenced (service checks) |
| Operational | attendance_records, project_updates, machine_usage_logs, assignments | Editable until locked (payroll/books lock); delete allowed before lock with audit |
| Documents/files | documents, files | Soft delete (`deleted_at`); binary purged by retention job after grace period (default 30 days) unless attached to financial records (then retained) |
| Security | sessions, auth_tokens, idempotency_keys | Hard delete by cleanup job after expiry |
| Audit | audit_logs | Append-only; never updated/deleted by the app (DB privileges) |

No global "soft delete middleware". Each repository applies its policy explicitly.

## 3. Entity catalog (owner module → tables)

Key columns only; all tenant-owned tables also have `tenant_id` + standard columns.

### Core
- **tenants** (`tenant`): name, legal_name, slug UNIQUE, status (ACTIVE|SUSPENDED|CLOSED), base_currency,
  timezone, locale, country_code, tax_id, address fields, logo_file_id, plan_code (future).
- **tenant_settings** (`settings`): tenant_id PK, `settings jsonb` (Zod-validated, versioned schema), version.
  Holds payroll proration basis, overtime defaults, approval thresholds, maker-checker flag, books_locked_until,
  numbering prefixes, notification defaults, file limits.
- **users** (`user`, global — no tenant_id): email citext UNIQUE, phone, name, password_hash, status
  (ACTIVE|DISABLED), email_verified_at, last_login_at, avatar_file_id NULL, is_platform_admin, mfa_* (future).
- **tenant_memberships** (`user`): tenant_id, user_id, status (INVITED|ACTIVE|DEACTIVATED), invited_by_id,
  joined_at, deactivated_at. UNIQUE (tenant_id, user_id).
- **permissions** (`authorization`, global catalog, seeded from code): code PK (`project.create`), module,
  action, description, supports_project_scope bool.
- **roles** (`authorization`): key, name, description, is_system, is_locked (Owner). UNIQUE (tenant_id, key).
- **role_permissions** (`authorization`): tenant_id, role_id, permission_code, scope (TENANT|ASSIGNED_PROJECTS).
  PK (role_id, permission_code).
- **membership_roles** (`authorization`): tenant_id, membership_id, role_id. PK (membership_id, role_id).
- **project_members** (`project`): tenant_id, project_id, membership_id, added_by_id. UNIQUE (project_id, membership_id).
- **sessions** (`auth`, global): user_id, token_hash UNIQUE, active_tenant_id NULL, ip, user_agent,
  created_at, last_seen_at, idle_expires_at, absolute_expires_at, revoked_at, mfa_verified_at.
- **auth_tokens** (`auth`, global): user_id, tenant_id NULL, type (PASSWORD_RESET|EMAIL_VERIFY|INVITATION),
  token_hash UNIQUE, expires_at, used_at.
- **audit_logs** (`audit`): see 21. Append-only.
- **outbox_events** (`core`): tenant_id, event_type, aggregate_type, aggregate_id, payload jsonb, occurred_at,
  processed_at, attempts, last_error. Index (processed_at NULLS FIRST, occurred_at).
- **idempotency_keys** (`core`): tenant_id, user_id, key, request_hash, response_status, response_body jsonb,
  created_at, expires_at. PK (tenant_id, user_id, key).
- **number_sequences** (`core`): tenant_id, sequence_key, prefix, next_value. PK (tenant_id, sequence_key).
  Incremented with `UPDATE … RETURNING` inside the business transaction (gap-free per committed row is **not**
  guaranteed on rollback — acceptable; documented to users as "sequential", not "gapless").
- **files**, **documents** (`files`, `document`): see 15.
- **notifications**, **notification_preferences**, **notification_deliveries** (`notification`): see 16.
- **report_exports** (`reporting`): report_key, params jsonb, format, status, file_id, requested_by_id, expires_at.

### Party
- **parties**: code, kind (ORGANIZATION|INDIVIDUAL), display_name, company_name, contact_person, phone, email,
  address fields, tax_id, notes, archived_at. Index GIN trgm (display_name), (tenant_id, phone), (tenant_id, email).
- **party_roles**: tenant_id, party_id, role (CLIENT|SUPPLIER|SUBCONTRACTOR|CONSULTANT|EQUIPMENT_PROVIDER|OTHER).
  PK (party_id, role).

### Project
- **projects**: code, name, client_party_id (composite FK → parties), location/address, site_lat/lng NULL,
  start_date, expected_end_date, actual_end_date, status (PLANNING|ACTIVE|ON_HOLD|COMPLETED|CANCELLED),
  description, archived_at. CHECK expected_end_date ≥ start_date. Index (tenant_id, status), trgm(name).
- **project_status_history**: project_id, from_status, to_status, reason, changed_by_id, changed_at (immutable).
- **project_parties**: project_id, party_id, role (ARCHITECT|CONSULTANT|OWNER_REPRESENTATIVE|OTHER). UNIQUE (project_id, party_id, role).
- **project_updates**: project_id, update_date, title, body, progress_percent NULL, weather NULL.

### Contract (includes client billing)
- **contracts**: project_id, contract_no, contract_type (LUMP_SUM|SQUARE_FEET|RUNNING_BILL|CUSTOM), contract_date,
  status (DRAFT|ACTIVE|COMPLETED|TERMINATED|CANCELLED), original_amount, measurement_area, measurement_unit
  (SQFT|SQM), rate_per_unit, payment_terms text, custom_terms jsonb, notes.
  **Partial unique index:** one non-cancelled contract per project: `UNIQUE (tenant_id, project_id) WHERE status <> 'CANCELLED'`.
- **contract_variations**: contract_id, variation_no, description, amount (±), status (DRAFT|APPROVED|REJECTED|CANCELLED), approved_by_id, approved_at.
- **client_bills**: project_id, contract_id NULL, bill_no, bill_date, due_date, period_from/to, description,
  gross_amount, deduction_amount, net_amount, status (DRAFT|SUBMITTED|APPROVED|CANCELLED|VOIDED), obligation_id NULL UNIQUE.

### Employee / Attendance / Payroll
- **employees**: code, name, phone, address, national_id (restricted), designation, skill_category, joining_date,
  exit_date, status (ACTIVE|INACTIVE|TERMINATED), user_id NULL (if also a system user), photo_file_id, archived_at.
- **employee_pay_rates**: employee_id, effective_from, effective_to NULL, pay_type (DAILY|MONTHLY|CONTRACT),
  daily_rate, monthly_salary, overtime_hourly_rate, standard_hours_per_day. **Exclusion constraint** (btree_gist)
  preventing overlapping ranges per employee (raw SQL in migration).
- **employee_assignments**: employee_id, project_id, role_on_project, start_date, end_date NULL.
- **attendance_records**: employee_id, project_id NULL, work_date, status (PRESENT|ABSENT|HALF_DAY|PAID_LEAVE|
  UNPAID_LEAVE|HOLIDAY), day_fraction numeric(3,2), hours_worked, overtime_hours, notes, source (WEB|MOBILE|IMPORT),
  payroll_run_id NULL (lock marker). `UNIQUE NULLS NOT DISTINCT (tenant_id, employee_id, work_date, project_id)`.
  Index (tenant_id, project_id, work_date), (tenant_id, employee_id, work_date).
- **payroll_runs**: run_no, period_start, period_end, pay_type (DAILY|MONTHLY|CONTRACT|MIXED), project_id NULL,
  status (DRAFT|CALCULATED|APPROVED|CANCELLED|VOIDED), calculated_at, approved_by_id, approved_at, notes.
- **payroll_items**: payroll_run_id, employee_id, pay_type, rate_snapshot jsonb, days_worked, overtime_hours,
  gross_amount, deduction_amount, adjustment_amount, advance_recovery_amount, net_amount, obligation_id NULL UNIQUE.
  UNIQUE (payroll_run_id, employee_id).
- **payroll_item_lines**: payroll_item_id, line_type (BASE|OVERTIME|ALLOWANCE|DEDUCTION|ADJUSTMENT|CONTRACT_WORK),
  project_id NULL, quantity, rate, amount (signed), description.

### Subcontractor
- **subcontracts**: subcontract_no, project_id, party_id (must have SUBCONTRACTOR role), scope_of_work,

## 4. Relationships & cardinality (summary)

| Relationship | Cardinality | Enforcement |
|---|---|---|
| tenant → everything | 1 : N | tenant_id FK + RLS |
| user ↔ tenant | N : M via tenant_memberships | unique pair |
| membership ↔ role | N : M | membership_roles |
| party ↔ role | 1 : N (party_roles) | PK |
| project → client party | N : 1 (required) | composite FK; service validates CLIENT role |
| project → contract | 1 : 0..1 active (N historical) | partial unique index |
| contract → variations | 1 : N | FK |
| employee → pay rates | 1 : N, non-overlapping | exclusion constraint |
| employee ↔ project | N : M over time via assignments | FK |
| attendance | employee × date × project unique | unique index |
| payroll run → items → lines | 1 : N : N | FK, unique (run, employee) |
| payroll item / subcontract bill / client bill / rental charge → obligation | 1 : 0..1 | UNIQUE obligation_id + UNIQUE (source_type, source_id) |
| obligation → lines | 1 : N (≥1) | service invariant: Σ lines = total |
| transaction ↔ obligation | N : M via allocations | Σ allocations ≤ amounts (service, row locks) |
| transaction → reversal | 1 : 0..1 | UNIQUE reversal_of_id |
| document → file | N : 1 | FK |
| document → owning record | polymorphic (entity_type, entity_id) + project_id | service validation (cannot FK) |

## 5. Transaction requirements (DB transactions)
Must be one database transaction (all-or-nothing), with `SELECT … FOR UPDATE` on the rows whose balances change:
- Recording a payment/receipt with allocations (lock obligations; re-check remaining amount).
- Expense "paid now" (obligation + lines + transaction + allocation).
- Approving a payroll run (items → obligations, advance recovery allocations, attendance lock, status change).
- Approving a subcontract bill / client bill / rental charge (obligation creation + status change).
- Voiding a transaction (reversal row, allocation reversals, obligation settled_amount/status recompute).
- Any change + its audit log row + its outbox events.
- Number sequence increment + the row that uses the number.
Isolation: READ COMMITTED + explicit row locks. Keep transactions short: no network calls (email, storage) inside.

## 6. Improvements over the source spec (and why)
1. **Transaction + Expense duplication removed.** The spec stored the same money fact in `Transaction` and
   `Expense`. Now: expenses are payable obligations; cash movement is a transaction; allocations link them.
2. **Obligations added** — spec requires outstanding balances (party, payroll, subcontract, rental, client) but
   had nowhere to hold "owed". Payroll `Paid/Due Amount` and rental `Payment Status` fields are now derived.
3. **Composite tenant FKs + RLS** — spec had `tenant_id` only on some tables (not on Contract, Attendance,
   Payroll, Document, Notification, Audit). Now on every tenant-owned table, enforced by the DB.
4. **User ↔ Tenant via memberships** instead of `users.tenant_id` — allows one person in several companies.
5. **Project status is an enum + history table**, not a "Project Status entity".
6. **Pay rates are effective-dated**; payroll items snapshot rates — rate edits never rewrite history.
7. **Contract cardinality clarified** (0..1 active + variations), client bills added for running bills and extra work.
8. **Documents are polymorphic attachments** (spec 5.17 allowed project only, 6.9 required transaction/employee).
9. **Money accounts added** (cash/bank/wallet) — needed for cash-flow reports; balances derived, not mutated.
10. **Machinery usage `cost`** removed from MVP costing to avoid double counting with fuel/repair expenses.
11. **Audit log** gains tenant_id, actor type, request id, and DB-enforced immutability.

## 7. Normalization notes
- Derived values (contract value incl. variations, party balance, project profit, account balance,
  obligation settled_amount) are **not stored**, except `settled_amount`/`status` on obligations, which are
  maintained transactionally by Finance only and verified by a nightly reconciliation job.
- Snapshots are intentional denormalization: payroll `rate_snapshot`, bill amounts, `documents.project_id`
  (for access filtering). Snapshots are never "synced" back.
- Do not copy party/project names into financial rows (the prototype did). Join at read time.

## 8. Scalability outlook
- Expected hot tables: financial_transactions, attendance_records, audit_logs, notifications, documents.
  With (tenant_id, …) leading indexes, tens of millions of rows remain fine on one PostgreSQL instance.
- When needed (not before): monthly partitioning of `audit_logs` and `attendance_records`; project financial
  summary table refreshed by events; read replica for reporting; archive old notifications.
- Avoid `COUNT(*)` on huge filtered sets for every list call — allow `includeTotal=false` / cursor feeds.

## 9. Migration rules
- Prisma Migrate only; migration files are reviewed like code. Raw SQL allowed in migrations for RLS policies,
  exclusion/partial constraints, extensions (`citext`, `pg_trgm`, `btree_gist`), and grants.
- **Expand → migrate → contract** for breaking changes (add nullable column, backfill, then enforce/drop).
- Never edit an applied migration. Never run `migrate reset`/`db push` against shared environments.
- Every new tenant-owned table must include in the same migration: tenant_id, composite unique, RLS policy,
  grants, and indexes. The tenant-isolation test suite must cover it (see 14).
